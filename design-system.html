The design system behind the lectures

One stylesheet, one runtime, twelve interactive components. Everything here is plain HTML, CSS and JavaScript with no build step and no dependencies, so a lecture is a single file an instructor can open from a USB stick or publish to GitHub Pages unchanged.

1 · Principles

Five decisions that everything else follows from. If a new component contradicts one of these, the component is wrong.

01 · Graphic first, then prose

A slide's job is to carry one idea visually. Reach for a diagram primitive before a bullet list, and for a bullet list before a paragraph. Paragraphs belong in the speaker notes.

02 · Interaction that teaches

Every interactive element exists to make a misconception visible, not to decorate. A popover holds the definition a student would otherwise guess; a check question exists because a specific wrong answer is common.

03 · Motion is barely there

120 to 180 milliseconds, opacity and a six-pixel rise. Nothing spins, bounces, or parallaxes. prefers-reduced-motion collapses it to nothing and the deck still works.

04 · Static pages, no build

No bundler, no framework, no CDN at runtime beyond the webfonts. A lecture works from file://, from GitHub Pages, and offline once cached.

05 · Accessible by construction

Keyboard parity for every mouse interaction, 20px type floor, AA contrast, one visible focus treatment, and no colour-only signalling.

2 · Colour

Red carries the brand and the slide frame; cedar green carries correctness and concepts; the neutrals are warm on the paper side and cool on the ink side, so a white slide never reads as clinical. 3 · Typography

Source Serif 4 for display and headlines — a scholarly voice with real optical sizing that survives projection. IBM Plex Sans for body, UI and captions. IBM Plex Mono for code, IRIs, identifiers and numeric columns. Three families, one job each.

Why 1600 × 900 and not 1920 × 1080

A teaching slide carries more text than a keynote slide. At 1600 the same physical type size is a larger number, which makes the 20px floor comfortable rather than a constant fight. The runtime scales the canvas to any screen, so projection is unaffected.

Self-hosting the fonts

The template loads the two families from Google Fonts. For a fully offline deck, drop the woff2 files into assets/fonts/, add @font-face rules to the @font-face block at the top of lu.css, and delete the three <link> tags from each lecture. Nothing else changes — the stack falls back to Georgia and the system sans, which are metrically close enough that layout does not break.

8 · Interactive components

Twelve components, all live below. Everything with a data-qid is graded and reports into the end-of-deck self-check automatically; give every one a unique id within the lecture. Answers persist in localStorage under the deck's own namespace and are never sent anywhere.

1 · Term popoverthe definition a student would otherwise guess.lu-term

The is why a reasoner will infer rather than complain. Click the term. Press Esc to dismiss, or S in a lecture to turn every popover into an inline note.

<button class="lu-term" type="button"
        data-term="open world assumption" data-kind="Semantics">
  open world assumption
  <template>Absence of a statement is <b>not</b> evidence…
    <p>A second paragraph for the thing not in the textbook.</p>
  </template>
</button>

Rich definitions go in the <template>. For a one-liner, use data-def="…" instead. data-kind is the small red category label.

2 · Click to revealhold an answer back so the room has to think.lu-reveal

Because consistency only asks whether some model exists. Declaring a domain and then attaching the property to the wrong class yields a valid entailment, not an error — the reasoner quietly reclassifies your data.

Real aria-expanded and aria-controls; the panel is hidden, so it is out of the accessibility tree until opened, and printed handouts force it open.

3 · Multiple choice with per-option feedbackgraded.lu-mcq

What does owl:sameAs assert between two IRIs?

<div class="lu-mcq" data-qid="s3-q1" data-answer="b"
     data-label="Short label for the self-check list"
     data-fb-correct=" Why it is right."
     data-fb-wrong=" What the wrong choice reveals.">
  <p class="lu-mcq__q">The question.</p>
  <div class="lu-mcq__opts">
    <button class="lu-mcq__opt" type="button" data-key="a">Option A
      <span class="lu-mcq__why" hidden>Why this is wrong.</span>
    </button>
    …
  </div>
  <div class="lu-mcq__fb" hidden></div>
</div>

Write a .lu-mcq__why for every option, including the correct one. The rationale is the teaching; the verdict is just bookkeeping. The runtime injects the A/B/C keys.

5 · Progressive buildsteps within a slide; deep-linkable as #/12/2data-build

Put data-build="1", "2", "3" on any elements. Same number means same step. The right arrow consumes build steps before advancing the slide, and the left arrow walks back through them. Two styles beyond the default rise:

data-build="1"Fades and rises in. The default.
data-build-style="dim"Present but at 28% opacity, then comes up to full. For a diagram that must be visible from the start.
data-build-style="hold"Occupies layout but invisible, so nothing shifts when it appears. For anything below the fold of a dense slide.
6 · Code block: copy, and run JavaScript in a sandbox.lu-code data-run="js"
const outsideEL = ['allValuesFrom', 'cardinality', 'complementOf'];
const used = ['someValuesFrom', 'cardinality'];
console.log(used.filter(c => outsideEL.includes(c)));

Copy is always available. data-run="js" adds a Run button that executes in a sandbox="allow-scripts" iframe with no page access, captures console output, and is killed after three seconds. Highlighting is hand-applied with .tok-* spans — there is no syntax-highlighting library to load.

7 · Drag to ordergraded · full keyboard alternative.lu-sort
  • Search for a published ontology
  • Write the competency questions
  • Extend it only where a question needs it

Correct order is ascending data-rank. Drag with a mouse, or use the injected up and down buttons — every drag interaction in this system has a button equivalent, which is the WCAG 2.2 dragging-movements requirement.

OWL 2 DL · HermiT · exponential worst case

Registration is the whole rule. Both panes are absolutely positioned on the same baselines, so a wipe only reads if the two versions line up — the same axiom, the same diagram, the same table with one column changed. Two different prose passages garble at the seam; for those use .lu-split and two columns. The seam is an <input type="range">, so it is keyboard-operable and labelled for free, and printing unclips both panes into two side-by-side columns.

10 · Live query sandboxSPARQL, offline, no server.lu-query

assets/sparql-lite.js is a teaching-sized engine: Turtle in a <template data-data>, and SELECT with a basic graph pattern, OPTIONAL, FILTER, GROUP BY, COUNT, ORDER BY and LIMIT. UNION, MINUS, BIND, property paths and subqueries raise a readable error rather than failing silently — say so in class and name what a real endpoint would do. Ctrl+Enter runs.

11 · Timed room pollgraded · countdown, then a manual tally.lu-poll

A class exists because the source table has a column for it. Keep it?

Honest limitation

A static page has no backend, so votes cannot be aggregated across devices. Each student's answer is recorded on their own machine; the instructor tallies the room with the plus and minus buttons after revealing. If you need true live aggregation, that is a service, not a slide — and it is the one thing in this system that would stop working offline.

12 · Self-checkcollects every graded component in the deck[data-score]

One empty <div data-score></div> on the last slide. It finds every component with a data-qid, reports attempted against correct, links back to the slide each question is on, and offers a clear-answers button scoped to this deck alone. The three demos above are feeding it right now.

9 · Runtime and keyboard

One script, assets/lu-deck.js, loaded with defer. It frames the slides, injects the chrome, and wires every component it finds. Ten runtime features, all keyboard-first.

Presenter view · P

Opens a second window with notes, the current and next slide, a wall clock, elapsed time and pacing. Synchronised over BroadcastChannel; arrow keys in either window drive both.

Deep links

#/12 is slide 12, #/12/2 is slide 12 at build step 2. Shareable, bookmarkable, and what the contents panel and search write.

Pacing · T

Sums data-minutes up to the current slide and compares it with elapsed time. Turns amber past two minutes behind, green when ahead.

Contents · O

Built from data-label, grouped by data-section, with the current slide marked. Focus is trapped and returned.

Search · /

Indexes the rendered text of every slide on first use and jumps to a hit. No index file to build or keep in step.

Study mode · S

Popovers become inline notes, reveals open, builds show, answers fill in. This is what a student who missed the session gets.

Handout

One page per slide with instructor notes appended, colours preserved, everything expanded. Print or save as PDF from the browser.

Saved state

Position, answers, query drafts and mode, in localStorage under lu:<deck-id>:*. Namespaced per lecture, cleared only by the user.

Offline · PWA

A service worker caches the shell and every visited lecture. Installable, and works on a train. Asset links carry a ?v= version; bump it when you edit assets/. Registration is skipped on file://.

Fullscreen and jump

F for fullscreen; type a number to jump to that slide; Home and End for the ends; ? lists everything.

10 · Accessibility contract

The target is WCAG 2.2 AA, and these are the specific commitments the system makes. A new component that breaks one of them is not finished.

CommitmentHow it is met
Text contrast 4.5:1, headline-scale 3:1Ink on paper is 13:1; the lightest permitted text, --lu-ink-3, is 4.6:1. Token comments record each ratio. No alpha-muted or color-mix text.
Keyboard parity with every pointer actionDrag ordering has up and down buttons; the compare wipe is a range input; walkthroughs respond to arrow keys; the popover closes on Esc.
Visible focus, never removedOne :focus-visible rule: 3px blue ring, 2px offset, recoloured on night grounds. Blue, not brand red, so focus never reads as an error.
Target sizeButtons are at least 48px high, 40px for the small variant, and 34px only for the auto-hiding chrome, which duplicates keyboard shortcuts.
Not by colour aloneCorrect and wrong carry a tick or cross glyph and a written verdict as well as green or red. Pipeline and layer states change border weight, not only fill.
Reduced motionprefers-reduced-motion collapses all durations to 1ms. No animation is load-bearing.
Screen-reader announcementsSlide changes and walkthrough captions go to polite live regions. Every slide is a labelled role="group" with aria-roledescription="slide" and an n of m label.
Focus management in overlaysContents, search and shortcuts are aria-modal dialogs with a tab loop and focus returned to the trigger.
Structure and languageOne lang, real heading levels, a skip link to the first content slide, and text in the DOM rather than baked into images.
Zoom and reflowNon-slide pages reflow to 320px. Slides are a fixed canvas by nature; the handout and study modes are the accessible route for anyone who needs to zoom into content.
Known gap, stated rather than hidden

A 1600×900 scaled canvas cannot satisfy the 1.4.10 reflow criterion the way a document can — that is inherent to slides, not to this implementation. Study mode and the printed handout are the conforming alternative versions, and every lecture links to them. Say this in a course accessibility statement rather than claiming full AA for the slide view.

11 · Rules for agents building lectures

The full brief is in AGENTS.md. These are the rules that get broken most often.

  1. Copy lectures/_template.html. Do not start from a blank file and do not restructure the frame.
  2. Never add a <style> block or an inline style that introduces a new colour, size or font. Layout nudges with the existing tokens are fine; new design decisions belong in lu.css.
  3. Every slide gets data-label, data-section, data-minutes and a <template data-notes>. Four attributes, no exceptions — three navigation features and the handout depend on them.
  4. Notes are for the instructor, not a transcript. What to say, how long to spend, the question the room will ask, the blocker that will appear at minute 20.
  5. Unique data-qid per graded component, prefixed with the session — s3-q1, not q1.
  6. Write a rationale for every option, including correct ones. A verdict without a reason teaches nothing.
  7. Diagrams: primitives, then SVG, then a placeholder. Never draw a screenshot or a photograph as SVG.
  8. Nothing below 20px, five bullets to a slide, sixty characters to a line. If it does not fit, the slide is two slides.
  9. Two grounds per deck. Paper and night, with tint to mark a change of activity. No third background colour.
  10. No emoji, no gradient backgrounds, no invented icon set. The type and the palette carry the tone.
  11. Add the finished lecture to index.html. A lecture nobody can navigate to does not exist.
