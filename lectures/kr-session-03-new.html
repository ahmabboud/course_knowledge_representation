Part 1 of 5 · about 25 minutes

One dataset. Three honest answers to “how many orders were late?”

The disagreement is not in the data. It is in the word.

Why this session exists

Same 65,752 DataCo orders. Three definitions of “late”. Three different answers.

Late means: any delay
57.3%

Real shipping days greater than the scheduled days.

Late means: the label says so
54.8%

The dataset's own column Delivery Status says “Late delivery”.

Late means: more than a day
23.7%

Real shipping days more than one day over schedule.

The problem

Every number is correct. A dashboard, a model and a report can each pick a different one, and nobody notices.

The fix this session builds

Write the meaning down once, precisely, in a form every program reads the same way.

The idea, drawn

An ontology names the kinds of things, and how things connect

Defined on this slide
Ontology
A machine readable description of kinds of things and how they relate.
Class
A named kind of thing, a box: Shipment.
Also defined here
Individual
One particular thing, a pill: carrier V444_1.
Property
A named connection, an arrow: handled by.
Kinds of things, arranged from general to specific

Classes form a tree. Read each line as “every … is a …”

Defined on this slide
Subclass
A is a subclass of B when every member of A is also a member of B.
owl:Thing
The class of everything. Every class sits somewhere below it.
Why a tree, not a list

A fact stated about Shipment is automatically true of every late, cancelled and at-risk shipment. You write it once.

Properties

An arrow points to a thing, or to a value. Notes are for humans only.

Defined on this slide
Object property
Links a thing to a thing: handled by.
Datatype property
Links a thing to a value (number, date, text): weight in kg.
Annotation property
A note for humans. The reasoner ignores it.
How an ontology file is organised

Rules about kinds of things above. Facts about particular things below.

Defined on this slide
Axiom
One statement in an ontology. Each white box above is one axiom.
TBox
The rules part: axioms about classes and properties.
ABox
The data part: axioms about individuals.
Why keep them apart

You can change the rules without touching the data, and load new data without touching the rules. The lab keeps them in two files.

Check question

Which of these is an ABox axiom, a fact about particular things?

Part 2 of 5 · about 40 minutes

How do you tell a machine what “at risk” means?

With a handful of words: some, only, and, or, not, exactly. Protégé shows them on every screen.

The picture behind every rule

Draw a class as a circle and its members as dots. Every rule says which dots may sit where.

Circle = class · dot = individual · a circle inside a circle = a subclass.

Defined on this slide
Member
An individual inside a class: a dot inside a circle.
Class as a set
OWL treats a class as exactly the set of its members.
The most used rule in OWL

some means: at least one arrow of this kind lands in that circle

Englishat least one carrier of this shipment is sanctioned
Protégé'handled by' some 'Sanctioned carrier'
Turtleowl:someValuesFrom ul:SanctionedCarrier
Defined on this slide
Restriction
A class described by a condition on a property.
some
Existential restriction: at least one link goes to a member of the class.
Manchester syntax
The readable way Protégé writes rules, with the words some, only, and, or, not.
The rule people misread

only means: no arrow of this kind lands outside that circle

The trap

A shipment with no carrier recorded still passes. only never says an arrow exists. To say both, write some and only.

Englishevery carrier of this shipment, if any, is sanctioned
Protégé'handled by' only 'Sanctioned carrier'
Turtleowl:allValuesFrom ul:SanctionedCarrier
Defined on this slide
only
Universal restriction: every link of this kind, if there is any, goes to a member of the class.
Combining classes

Four ways to combine circles. The shaded area is the new class.

and · intersection

Members of both classes.

Shipment and ('handled by' some 'Sanctioned carrier')

or · union

Members of either class.

Plant or Port

not · complement

Everything outside the class.

Carrier and not 'Sanctioned carrier'

disjoint

Classes that share no member.

'Late shipment' DisjointWith 'Cancelled shipment'

Every example is written the way Protégé shows it. The disjoint one is a real axiom in our lab file.

Rules that count

Some questions need a number: exactly one supplier, at least two routes

In the Brunel data

V444_0 ships on 2 lanes, V44_3 on 3, V444_1 on 1. Two of the three carriers would count as multi-route.

Defined on this slide
Cardinality restriction
A rule that counts links: exactly 1, min 2, max 3.
Remember this for Part 5

The fast reasoner used first in the lab, ELK, ignores counting rules. That is why it misses one of the lab's two errors.

The biggest surprise for database people

The same fact: a database rejects it, OWL learns from it

INSERT INTO handled_by
  VALUES ('1447311670.7', 'V444_1');

IntegrityError: FOREIGN KEY constraint failed
Defined on this slide
Domain
The class every subject is inferred to be in.
Range
The class every object is inferred to be in.
Entailment
A fact that follows, though nobody wrote it.
Why the reasoner sometimes does nothing

A one way door, or a two way door. Only the two way door lets the reasoner classify data.

Rules about the arrows themselves

A property can carry its own rules, and the reasoner uses them

Transitive

If A is part of B and B is part of C, then A is part of C.

Functional

At most one value per subject: one order date per order.

Inverse

The same link read backwards: handled by and handles.

Also: punning

Using one name as both a class and an individual. OWL 2 allows it, but it confuses people and tools. Avoid it unless you truly need it.

Part 3 of 5 · about 27 minutes

Our file carries 4,819 axioms. Who checks that none of them contradict each other?

Nobody, by hand. A reasoner does, in seconds, and tells you exactly which axioms are to blame.

Why a reasoner

Our small extension imports SCRO, IOF Core and BFO: 4,819 axioms, 254 classes

Defined on this slide

Reasoner: a program that works out every fact that follows from an ontology's axioms.

Inference: a fact the reasoner derived that nobody wrote down.

Open world, one more time

The reasoner never assumes a missing fact is false. No carrier recorded means unknown, not none.

What a reasoner actually does for you

Three jobs, each finding a different kind of mistake

Consistency

Can this ontology have any model at all? One thing in two disjoint classes: no.

Classification

Compute the full tree, including subclass links nobody wrote.

Realization

For every individual, compute every class it belongs to.

Defined on this slide
Subsumption
The “is a subclass of” relation, stated or inferred.
Consistency check
The test that the ontology does not contradict itself.
What an error looks like

A class that can never have a member turns red, under owl:Nothing

Defined on this slide

Satisfiable class: a class that could have at least one member without contradiction.

Unsatisfiable class: a class that can never have a member. Protégé shows it red.

owl:Nothing: the empty class. An unsatisfiable class is equivalent to it.

Not a crash, a finding

Nothing failed. The reasoner proved that our own definition asks for something impossible. The lab finds out why.

Diagnostic walkthrough

One careless fact, four steps, and the reasoner stops everything

Real run

python local_reasoner.py workspace/domain-mistake.ttl answers: the ontology is inconsistent.

The lesson

A domain is a promise about every subject. Attach the property to the wrong kind of thing and the reasoner believes you, all the way to a contradiction.

Why is the class red?

Click the ? next to a red class: Protégé lists the few axioms that together cause it

Defined on this slide
Justification
The smallest set of axioms that together cause an inference. Remove any one and the inference goes away.
How to read it

Line 1 is the only line we wrote. Lines 2 to 6 were imported. So the mistake is in how line 1 uses SCRO. Part 4 decodes lines 2 to 6.

Check question

After the reasoner runs, Late shipment appears under At-risk shipment, which nobody intended. Which job surfaced it?

Part 4 of 5 · about 30 minutes

Industrial ontologies for supply chain already exist. Why build your own?

Not reusing them is a decision, not a default. And reusing them has a price: you inherit their rules.

Where our classes attach

Three published layers under us. We only write what they do not already say.

Defined on this slide

Upper ontology: a very general ontology of basic categories that domain ontologies build on. BFO is an ISO standard one.

IOF · SCRO: the Industrial Ontologies Foundry's core layer, and its Supply Chain Reference Ontology, the base we extend.

Alignment: linking our classes to classes in another ontology.

BFO's first split

Everything is either a thing that lasts, or something that happens

Defined on this slide
Continuant
Something that persists through time: a truck, a warehouse, a purchase order.
Occurrent
Something that happens and unfolds in time: a delivery.
Process
An occurrent with parts that happen one after another: loading, then shipping.
Three kinds of continuant

Some things stand on their own. Some exist only in one bearer. Some can be copied.

Defined on this slide

Independent continuant: exists on its own; a material entity is made of matter.

Specifically dependent continuant: exists only in one bearer: a quality, a role.

Also defined here

Generically dependent continuant: information that can be copied between bearers.

The lab's red class, explained

We borrowed a SCRO property for its name, and inherited a rule we did not know about

The fix

Do not reuse a property for its name. Use our own, ul:hasComponent and ul:suppliedBy, which say exactly what we mean. The reference file does; the lab applies it.

Method · drag or use the arrow buttons

Put the method in the order you will actually work in.

  • Extend SCRO only where a question needs a class it lacks
  • Write the competency questions the organisation actually asks
  • Read the inferred tree and fix the model, not the output
  • Search for a published ontology that already answers them
  • Run ELK, then HermiT
Defined on this slide
Competency question
A question the ontology must be able to answer. It decides what belongs in the ontology.
In our file

Every class carries the question it answers, as a ul:answersCQ note. Eight questions, listed in competency_questions.md.

Linking to other ontologies

Two linking axioms that look harmless and are not

Defined on this slide

owl:sameAs: two names for exactly the same individual. The reasoner merges everything said about them.

owl:equivalentClass: two classes with exactly the same members. Every rule on one applies to the other.

Safer

Prefer rdfs:subClassOf until you can defend the equivalence. Keep “probably the same” for Session 5's entity resolution, with a confidence.

Part 5 of 5 · about 14 minutes

One decision decides whether your reasoner finishes at all. Which one?

How much of OWL you use. Less OWL, faster answers, and some questions you can no longer ask.

OWL profiles

Pick the part of OWL your workload can afford

ProfileBuilt forGives upReasoner
ELVery large class treesonly, counting, notELK, fast
QLQueries over a relational databaseseveral constructs, to rewrite into SQLOntop, Session 5
RLRule enginesreasoning about unnamed thingsrule engines
DLEverything OWL can saynothing, but can be slowHermiT, complete
Each of our classes records the profile it was written for, in a ul:profile note.
Defined on this slide

OWL profile: a restricted part of OWL chosen so reasoning stays fast.

Decidable: a program is guaranteed to finish with the right answer. OWL DL is; full first order logic is not.

ELK · HermiT: a very fast EL reasoner that ignores the rest; a complete, slower DL reasoner.

So what

A fast reasoner that says “no errors” only means no errors it can see. Run the complete one before you ship.

Licence literacy is part of reuse, not an administrative detail

  1. Open the SCORVoc repository, vocol/scor, on GitHub.
  2. Find the ODC PDDL licence declared inside scor.ttl.
  3. Find the all rights reserved notice in the same repository's README.
  4. Decide which governs. Write why, in two sentences.
Why it is here

It is one reason this course builds on IOF SCRO (MIT licence), not SCORVoc. An ambiguous licence is itself the finding.
