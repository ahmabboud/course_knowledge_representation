Part 2 of 4 · about 30 minutes

How does a model learn which plant makes a product it has never been told about?

Give every thing a position, so that true links become short steps.

The idea behind knowledge graph embeddings

Every thing gets a position. A relation is a step. A true link is a short trip.

Defined on this slide
Embedding
A short list of numbers learned for each thing, so that related things end up close.
TransE
An embedding where head + relation should land near the tail.
The score

score(h, r, t) = − distance(h + r, t). Close: likely true. Far: likely false.

The same idea, four scoring functions

They differ in which patterns of relations they can represent

ModelHow a triple is scoredSymmetricAntisymmetricInverseComposition
TransE, 2013h + r lands near tnoyesyesyes
DistMult, 2015h, r and t multiplied, number by number: every relation symmetricyesnonono
ComplEx, 2016DistMult with complex numbers: a relation can go one wayyesyesyesno
RotatE, 2019r rotates h onto t, in complex numbersyesyesyesyes
For Brunel

Every relation links two different kinds (a plant makes a product; a product never makes a plant), so none is symmetric. TransE fits: it is the one the lab trains.

Walkthrough · how training learns what is false

The graph holds only true links. Training makes up false ones to compare.

Defined on this slide
Negative sampling
Making up false triples by swapping the head or the tail, so the model learns to score them lower.

Part 3 of 4 · about 30 minutes

How does an order learn from the things it is linked to?

Each thing sends its numbers along its links; each order combines what it receives.

Walkthrough · the order from Part 1

A layer mixes each node's own numbers with its neighbours'

Defined on this slide
Message passing
Each node updates itself from what its neighbours send it, one round per layer.
GraphSAGE
A layer where a node combines its own numbers with the average of its neighbours'.
How many other orders has one order heard from, after k layers?

On Brunel, two layers already reach almost every order

1 layer · its 5 neighbours0 orders
2 layers · through a shared port or carrier9,074
4 layersall 9,214
Defined on this slide
Oversmoothing
After many layers every node has heard from the same crowd, so all their numbers look alike.
Why the lab stops at 2

PORT04 alone serves 9,041 orders. More layers add no new neighbours, only more averaging.

Defined on this slide
HeteroData
PyTorch Geometric's object for a graph with several kinds of node and link.
ToUndirected

Every link points from the order outward. Messages flow along links, so without the reverse links an order would receive nothing at all.

Where Session 3 pays off

Classes become node kinds, properties become link kinds

In the ontologyIn HeteroData
ul:Order, and its subclass ul:LateOrderone node kind: order
ul:Customer, ul:Carrier, ul:Plant, ...one node kind each
ul:orderedBy (domain Order, range Customer)one link kind: order to customer
ul:makes (domain Plant, range Product)one link kind: plant to product
A subclass is not a kind

LateOrder ⊑ Order, so build_graph.py makes one kind, order. A separate kind for late orders would be the label.

Better ontology, better graph

A property with a clear domain and range becomes one clean link kind. A vague one mixes different things in one list.

What gnn.py trains

Write the model for one kind of link. to_hetero copies it for all fourteen.

class SAGE(torch.nn.Module):
    def __init__(self):
        self.conv1 = SAGEConv((-1, -1), 32)
        self.conv2 = SAGEConv((-1, -1), 32)
        self.score = Linear(32, 1)
    def forward(self, x, edge_index):
        h = self.conv1(x, edge_index).relu()
        h = self.conv2(h, edge_index).relu()
        return self.score(h)

model = to_hetero(SAGE(), data.metadata(), aggr="sum")
Defined on this slide
to_hetero
PyTorch Geometric's tool that copies a model once per kind of link.
A real gotcha

The argument must be called edge_index. Named ei, to_hetero failed with an error that never said why.

Defined on this slide
RGCN
Relational graph convolutional network: a layer with one weight matrix per kind of link.
Weights multiply

to_hetero gave 236,870 weights for 14 kinds of link: each new kind adds a full copy. RGCN can share a few basis matrices instead.

What happens when something appears that training never saw?

Some models learn a position per thing, some learn a rule

Transductive · TransE

One position per thing seen in training. A new product has none.

CND9 makes one product. When that link is hidden, CND9 has no position, and the lab ranks it last for every other product.

Inductive · GraphSAGE

Learns weights, not positions: a new order gets numbers from its neighbours.

But a customer's numbers only say which one it is. A new customer is a column the model never trained.

Defined on this slide
Transductive
A model that can only score things it saw in training.
Inductive
A model that can score new things, from their numbers and neighbours.

Report the spread

Run several seeds and give the range, not the best run. Seed 0 alone would say the GNN is twice as good; seed 1 says they tie.

An empty test

Seed 4 put none of the four customers in the test: no late order at all, so PR-AUC is undefined.

The rule for your project: train on the past, test on the future

Brunel cannot do this: all 9,215 orders are dated 2013-05-26

  1. Pick a cut date. Everything after it is the test.
  2. Build the training graph from before the cut only: a link created later is the future too.
  3. If the same customers appear on both sides, also report a split by customer.
Defined on this slide
Temporal split
Training on everything before a cut date and testing on everything after it.
Temporal leakage
Letting information from after the cut into training.

def split_by_customer(customer, test_share=0.3,
                      seed=0):
    rng = np.random.RandomState(seed)
    groups = np.unique(customer)
    rng.shuffle(groups)
    n_test = int(round(test_share * len(groups)))
    test_groups = groups[:n_test]
    in_test = np.isin(customer, test_groups)
    return (np.flatnonzero(~in_test),
            np.flatnonzero(in_test))

Discussion · as a room, from Part C

Both graph models lost today. Is that a failure?

  1. TransE lost to a count. What would the graph need for its shape to beat popularity?
  2. GraphSAGE won only where it could remember customers. How would you write that in a report without hiding it?
  3. Your own data: which field is the date, and which group (customer, supplier, site) must not be on both sides?
Why losing is reportable

It says, with evidence, that the simple model is enough for this task on this data. That saves a company from running, and trusting, a model that only looks better.
