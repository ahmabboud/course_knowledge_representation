Part 1 of 5 · about 14 minutes

The database changed overnight. Do we rewrite the converter?

No. We describe once how rows become triples, and let a tool do it.

The idea

Same tables, same graph. The difference is who does the work.

Defined on this slide
Mapping
Rules that turn rows of a table into triples.
R2RML
The W3C language for mappings from relational databases to RDF (2012).
Why it matters

A mapping is a file any R2RML tool can run, and anyone can read. A converter is code only its author knows.

Materialize or virtualize

Store the graph, or translate every question. One mapping does both.

Defined on this slide
Materialization
Converting the data to triples once and storing them.
Also defined here
Virtualization
Leaving the data in its database and translating each SPARQL query into SQL.

RML
RDF Mapping Language: R2RML extended to CSV, JSON and XML sources.
Walkthrough

A subject from the key, then one rule per column

The same rules, written down

A table, a subject, and one predicate-object map per column

<#Orders>
  rr:logicalTable [ rr:tableName "orders" ] ;
  rr:subjectMap [ rr:template
    "https://ul.edu.lb/kr/id/order/brunel/{order_id}" ] ;
  rr:predicateObjectMap [ rr:predicate ul:orderId ;
    rr:objectMap [ rr:column "order_id" ] ] ;
  rr:predicateObjectMap [ rr:predicate ul:weight ;
    rr:objectMap [ rr:column "weight" ;
                   rr:datatype xsd:decimal ] ] .
Defined on this slide
Triples map
One table or query, and the triples each of its rows becomes.
IRI template
A pattern that builds an IRI from a column: {order_id} is replaced by the row's value.
Read it as English

For each row of orders, make the order's IRI; give it the id as text and the weight as a decimal.

Foreign keys

The carrier's IRI is built from the key in the order's own row

rr:predicateObjectMap [ rr:predicate ul:carriedBy ;
  rr:objectMap [ rr:template
    "https://ul.edu.lb/kr/id/carrier/brunel/{carrier}"
  ] ] ;
A column, or a template?

rr:column "carrier" would give the text "V44_3". rr:template gives the carrier's IRI: a link to the same node the carriers map makes.

Why no join

Both maps use the same template, so they build the same IRI for V44_3. R2RML can also join tables (rr:parentTriplesMap); with a naming rule like ours, it rarely needs to.

Session 4's triage, fixed

An SQL query as the source: every carrier from both tables, typed once

<#Carriers>
  rr:logicalTable [ rr:sqlQuery """
    SELECT carrier FROM orders
    UNION
    SELECT carrier FROM freight_rates""" ] ;
  rr:subjectMap [ rr:template
    "https://ul.edu.lb/kr/id/carrier/brunel/{carrier}" ;
    rr:class ul:Carrier ] .
Defined on this slide
Logical view
An SQL query used in place of a table, to prepare or combine rows first.
The fix

Session 2 typed a carrier only when an order used it: 3 carriers. This view finds all 10. Session 4's 1,209 untyped rate bands: gone.

Two small maps, one per class

An order with late days is a late order: a filter chooses the class

<#LateOrders>
  rr:logicalTable [ rr:sqlQuery """
    SELECT order_id FROM orders
    WHERE ship_late_day_count > 0""" ] ;
  rr:subjectMap [ rr:template
    "https://ul.edu.lb/kr/id/order/brunel/{order_id}" ;
    rr:class ul:LateOrder ] .
The twin

<#OnTimeOrders> is the same map with = 0 and rr:class ul:Order: 9,023 orders and 192 late orders, as in Session 2.

Same subject, several maps

Three maps make the same order IRI: the properties, the date, the class. The triples simply add up.

Rate bands

No column, and no combination of columns, names one rate band

FreightRatesCount
rows in FreightRates1,540
different rows1,537 (5 rows are exact copies of another)
different on carrier, ports, service, minimum weight1,258
rr:subjectMap [ rr:template "rate-band-{rate_id}" ;
  rr:termType rr:BlankNode ; rr:class ul:RateBand ] ;
The decision

A band gets no permanent IRI. It is a blank node, one per row, told apart by the row number the loader adds. As in Session 2.

Why not invent a key?

An IRI promises that the same name means the same thing tomorrow. A row number cannot keep that promise; a blank node makes none.

Drill · type the missing word

Fill in the blanks

  1. To build the order's IRI from its key, the subject map uses an rr:.
  2. To copy a column as a plain value, the object map uses rr:.
  3. To make the weight a decimal, add rr: xsd:decimal.
  4. An SQL query used as a source is written with rr:.

Choosing a route

Neither wins: each gives up something the other keeps

Materialize · Morph-KGCVirtualize · Ontop
Answers are currentno: a snapshot, until the next runyes: every query asks the live tables
Query speedfast: the graph is storeddepends on the database and the SQL
SHACL validationyes: the shapes need a graph to readno: nothing is stored to check
Spacea second copy of the datanothing extra
Changes to the mappingrun it againeffective at the next query
A common answer

Virtualize for live questions, and materialize on a schedule for validation and for Session 6's learning, from the same mapping.

Defined on this slide
Entity resolution
Deciding which records in different sources describe the same real thing.
Teaching data

Brunel has no second system. A script wrote this TMS list from Brunel's 46 real customers, plus 6 that are not in Brunel. So the truth is known, and errors can be counted.

Two cheap steps before any scoring

Cleaning fixes the easy drift. Blocking skips pairs that cannot match.

1 · Clean both sides the same way

Upper case, spaces off, dash to underscore, the V back, _023 to _23.

4 of the 6 drifts above now match exactly. A lost 5 and swapped digits do not.

2 · Block on the home plant

Blocking: only comparing records that share a cheap key, here the home plant.

Match weight
log2(m / u): m is how often the outcome happens for a true match, u for two different customers.
