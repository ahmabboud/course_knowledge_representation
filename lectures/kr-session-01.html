Part 2 of 7 · about 42 minutes

What is knowledge, and why does a computer need it written down?

From a single number to an engine that answers questions nobody stored. Nothing here needs a computer science background.

The payoff first

One question, three ways to answer it. Only one can show why it is right.

Knowledge graph Data stored as things connected by named relationships, together with the ontology that says what they mean.

What makes it knowledge

A number becomes knowledge when it has context, links to other facts, and rules.

Experience Judgement built from many past cases. The level of knowledge hardest to write down.

Every medium stores more and loses something

People have always written knowledge down. Each step fixed one limit and left the next.

The pattern

Every step stores more. None of them answers a question by itself: a person still reads, connects and judges.

Digital storage 1 · relational tables

Tables store facts well. The links between them are worked out when you ask.

SQL Structured Query Language: the language for asking questions of relational (table) databases.

Digital storage 2 · the data warehouse

A warehouse is built to add things up fast. It is not built to follow connections.

Data warehouse A database that copies and cleans data from many systems on a schedule, shaped for fast sums and history. Star schema A warehouse layout: one fact table of measures with a few descriptive tables around it. Operational data The current data that running systems write as things happen: fast and in small pieces.

Digital storage 3 · graphs

A graph stores the links themselves, so following them is one walk, at any depth.

What the course adds to a graph

A graph database stores the links. A knowledge graph also knows what they mean.

Constraints

Storing facts is not enough. Someone has to say which facts are allowed.

The engine

Facts plus a rule give an answer nobody wrote down, and the system can show why.

Why this matters now

A language model talks well. A knowledge graph knows what is true here. Together they answer, with proof.

LLM agent A language model that decides which tool to call, such as a query to a knowledge graph, and uses the result. LLM Short for large language model.

RAG, and what a graph adds

RAG means retrieve first, then let the model answer from what was retrieved.

A model aloneRAG over textGraph grounded
It retrievesNothingPassages like the questionFacts and paths, by a query
Good atLanguage, general facts"What does this say?"Connections, counts, rules, why

Honest note

They combine, and many systems use both. How much a graph beats plain RAG depends on the questions: test it on yours. Session 7 does.

RAG Retrieval augmented generation: find relevant material first, then let a language model answer from it.

Use it where it pays

A knowledge graph is the right tool for some problems and the wrong tool for others.

It fits when

Many systems name the same thing differently. The questions are about connections or "how many steps". Rules must hold and be explained. The knowledge lives for years and many teams share it. An answer must show why it is right.

It fits badly when

One clean table answers fixed reports: use a warehouse. You add up billions of rows: use a warehouse. You need thousands of fast transactions: use an operational database. The data is mostly free text and nobody will keep a model: use search. It is a one-off analysis.

Where it sits

Beside the operational database (fast, now) and the warehouse (history, sums), not instead of them. It is the layer that connects what they hold and says what it means.

Say this one out loud

Integration rarely fails because data is dirty. It fails because two correct descriptions of the world meet, and nobody wrote down how they differ.

Same data, same question, two answers

How many DataCo order lines were late? It depends on what "late" means.

Check question

The habit this trains

Measure 4 · links between tables

Every order names a carrier. Does every carrier have a price?

Defined on this slide
Referential integrity
Every reference points at something that exists, for example every order's carrier has a row in the rate table.

Service level A short code for how an order is shipped and how fast. Brunel's codes are CRF, DTD and DTP. CRF A service level code in Brunel's OrderList, used on 854 orders, all with carrier V44_3. The file never defines it.

One slide for the tool

ydata-profiling measures every column and lists what looks odd.

  1. Constant: Order Date and Destination Port.
  2. Zeros: Ship Late Day count, 97.9 percent.
  3. Order ID typed as a real number: an identifier with a decimal point.
Measure 5 · near duplicates

Clustering suggests values that may be one thing. You decide.

Defined on this slide
Clustering (of values)
Grouping values that look alike, such as two spellings, so a person can decide whether they mean the same thing.

Fingerprint A key made from a value by removing case, accents and punctuation and sorting its words. Values with the same key form a cluster.

Discussion · which stage broke?

Three failures. Name the stage of the architecture that broke.

Case A

A recall went to 400,000 customers because the one plant at fault could not be traced.

Integration. The parts list lived in one system and was never linked to shipments.

Case B

A dashboard said 12 percent of shipments were late. Operations said 30. Both computed correctly.

The ontology, by its absence. Two meanings of "late", like our 98,977 and 103,400.

Case C

An assistant answered fluently about a supplier removed eight months before.

The question layer. It could not say "stale" or "I do not know". Session 7 grades that.

Then, as a room: compare inventories and count the rules only one person found. That number is the argument for writing meaning down.
